For repository maintainers

AI-generated PRs?
Ask the human first.

Put four questions in your contribution rules. Ask the person behind the agent to explain who benefits before it writes code.

Copy the gateView on GitHub

No bot or dependencies. Works only with agents that read and follow your repository instructions.

Four questions before code

  1. What outcome do you really want?
  2. What is the highest-leverage variable that determines it?
  3. Will this work move that variable, or just keep you busy?
  4. Who is the customer, and what do they really want?

The human answers. The agent waits.

“Customer” can mean a user or a maintainer. Reuse answers for the same contribution; ask again if the goal changes.

Add it to your repo

Install automatic instructions for Claude Code, Codex, and Pi with Node.js 20 or later. Preserve your existing contribution rules and agent configuration.

git clone https://github.com/ktwu01/agent-pr-gate.git
node agent-pr-gate/scripts/install.mjs --target /path/to/your/repo --agents claude,codex,pi

Choose one agent or a comma-separated list. Claude Code loads CLAUDE.md; Codex and Pi load AGENTS.md. No hook or extension is installed. Restart your agent in the target repository after installation. Instruction overrides and context settings can affect loading.

Read-only exploration does not trigger the questions. The instructions ask agents to wait for human answers before changing files or drafting a PR. This does not block tools or enforce PR approval.

For a manual install, append these sections to your existing files at the repository root.

CONTRIBUTING.md

<!-- https://github.com/ktwu01/agent-pr-gate -->
## Before you start a PR

Read-only exploration is allowed without answering these questions. Do not ask merely because a session starts.
Before changing files or drafting a PR, ask your human these questions and wait:

1. What outcome do you really want?
2. What is the highest-leverage variable that determines it?
3. Will this work move that variable, or just keep you busy?
4. Who is the customer, and what do they really want?

The human must answer. Do not answer for them, invent answers, or infer answers from the task request.
Ask only unanswered questions. Reuse answers explicitly given for this contribution.
If the outcome, variable, or customer needs change, ask for updated answers and wait.
After all four answers, consider whether the outcome needs a PR at all.
Include brief, non-sensitive answers in the PR description. Omit private details.
Send one contribution and wait for review before sending more.

AGENTS.md

<!-- https://github.com/ktwu01/agent-pr-gate -->
## Contributions

Read-only exploration does not require answering the gate. Do not ask merely because a session starts.
Read CONTRIBUTING.md before changing files or drafting a PR.
Follow its four-question gate: ask the human for missing answers and wait.
Do not supply or infer the human's answers yourself.
Reuse their explicit answers for this contribution. Ask for updates if the goal changes.

These are independent accounts of review workload. They are not endorsements or evidence of this gate's effectiveness.

Before you adopt it

Does this block AI PR spam?

It is a contribution policy, not an enforced blocker. An agent can ignore it, and a spam script can skip it. Pair it with an open-PR limit and clear acceptance criteria.

Can I still accept AI-assisted contributions?

Yes. Ask the contributor to check their work and explain the need. Judge the contribution by its usefulness and evidence.

Do I need a bot, package, or paid service?

No. Copy the text into CONTRIBUTING.md and AGENTS.md. The contributor's agent must read and follow those files.

How can I help evaluate it?

Report an observation: which agent you used, whether it asked and waited, and your time window. Share public or synthetic examples only. Reports of failure are useful too.
